# 🟢 Result Pattern in .NET

In modern .NET applications (Clean Architecture, CQRS, EF Core, APIs), returning **consistent results** is very important. Instead of returning only `null`, `true/false`, or throwing exceptions randomly, we use a **Result Pattern**.  

This makes code **predictable, testable, and beginner-friendly**. 🚀  

---

## 📖 What is the Result Pattern?

The **Result Pattern** is a way to represent the **outcome of an operation** in a structured manner.  
It wraps both success and failure states in a single object.

👉 With Result Pattern, you always know:  

- ✅ Was the operation successful?  
- ❌ Did it fail?  
- 📜 If failed, why did it fail? (Error message, error type, status code)  
- 📦 If successful, what data/value do we return?  

---

## 🎯 Why Use Result Pattern?

1. **Consistency** → Every method returns the same predictable object.  
2. **Error Handling** → No need to throw exceptions everywhere.  
3. **Separation of Concerns** → Business logic = business only, error handling = centralized.  
4. **Clean API Responses** → Easy to return proper HTTP codes (200, 404, 400, etc.) in APIs.

## 🛠 Implementation

### 1️⃣ Define `ResultType` Enum
```csharp
public enum ResultType
{
    Ok,
    NotFound,
    Forbidden,
    Conflicted,
    Invalid,
    Unauthorized,
    Error
}
````

---

### 2️⃣ Base Class `ResultCommonLogic`

Ensures that rules are followed:

* Success → No error message allowed
* Failure → Error message is mandatory

```csharp
public abstract class ResultCommonLogic
{
    private readonly string _message;

    public bool IsFailure { get; }
    public bool IsSuccess => !IsFailure;
    public string Message => _message;
    public ResultType ResultType { get; }

    public HttpStatusCode HttpStatusCode => ResultType switch
    {
        ResultType.Ok => HttpStatusCode.OK,
        ResultType.NotFound => HttpStatusCode.NotFound,
        ResultType.Forbidden => HttpStatusCode.Forbidden,
        ResultType.Conflicted => HttpStatusCode.Conflict,
        ResultType.Invalid => HttpStatusCode.NotAcceptable,
        ResultType.Unauthorized => HttpStatusCode.Unauthorized,
        _ => HttpStatusCode.InternalServerError,
    };

    protected ResultCommonLogic(ResultType resultType, bool isFailure, string message)
    {
        if (isFailure)
        {
            if (string.IsNullOrWhiteSpace(message))
                throw new ArgumentNullException("message", "Failure requires an error message.");
            if (resultType == ResultType.Ok)
                throw new ArgumentException("Failure cannot have Ok as resultType.");
        }
        else
        {
            if (!string.IsNullOrWhiteSpace(message))
                throw new ArgumentException("Success cannot contain an error message.");
            if (resultType != ResultType.Ok)
                throw new ArgumentException("Success must have ResultType.Ok.");
        }

        ResultType = resultType;
        IsFailure = isFailure;
        _message = message;
    }
}
```

---

### 3️⃣ Generic Result Class

Used when we need to return **both data and status**.

```csharp
public class Result<T> : ResultCommonLogic
{
    public bool IsEmpty => Value == null || Value.Equals(Empty);

    public T Value { get; }
    private static T Empty => default(T);

    internal Result(ResultType resultType, string message)
        : base(resultType, isFailure: true, message)
    {
        Value = Empty;
    }

    internal Result(T value)
        : base(ResultType.Ok, isFailure: false, string.Empty)
    {
        Value = value;
    }

    public static implicit operator T(Result<T> result) => result.Value;

    public static implicit operator Result(Result<T> result)
    {
        return result.IsSuccess ? Result.Ok() : new Result(result.ResultType, result.Message);
    }
}
```

---

### 4️⃣ Non-Generic Result Class

Used when only success/failure is needed.

```csharp
public class Result : ResultCommonLogic
{
    internal Result(ResultType resultType, string message)
        : base(resultType, isFailure: true, message) { }

    internal Result() : base(ResultType.Ok, false, string.Empty) { }

    public static Result Ok() => new Result();
    public static Result Fail(ResultType type, string message) => new Result(type, message);
}
```

## 🚀 Example Usage

### Service Layer

```csharp
public async Task<Result<UserDto>> GetUserByIdAsync(string id)
{
    var user = await _userRepository.FindByIdAsync(id);
    if (user == null)
        return Result<UserDto>.Fail(ResultType.NotFound, $"User {id} not found");

    return new Result<UserDto>(new UserDto(user.Id, user.UserName));
}
```

### Controller

```csharp
[HttpGet("{id}")]
public async Task<IActionResult> GetUser(string id)
{
    var result = await _userService.GetUserByIdAsync(id);

    if (result.IsFailure)
        return StatusCode((int)result.HttpStatusCode, result.Message);

    return Ok(result.Value);
}
```
