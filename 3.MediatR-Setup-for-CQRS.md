# 📝 Guide: How to Implement Your Own MediatR in .NET

MediatR ek popular library hai jo **CQRS (Command Query Responsibility Segregation)** aur **decoupled architecture** me use hoti hai. Lekin agar aap apna custom MediatR banana chahte ho, to ye guide step by step samjhata hai.

---

## 1️⃣ Step 1: Create Command & Handler Abstractions

### 🔹 ICommand Interface

```csharp
using Authentication.Common.Result;

public interface ICommand<TResult> where TResult : ResultCommonLogic
{
}
```

#### Explanation:

1. `ICommand<TResult>` ek **marker interface** hai.

   * Ye signal karta hai ki ye ek command hai.
   * `TResult` ka matlab hai ki ye command ek result return karega.

2. `where TResult : ResultCommonLogic`

   * Ye **generic constraint** hai.
   * Matlab `TResult` sirf **ResultCommonLogic** ya uske derived types ho sakte hain.
   * Yeh compile-time safety provide karta hai.

**Simple example:**

```csharp
public class LoginResult : ResultCommonLogic { }
public class LoginCommand : ICommand<LoginResult> { }
```

---

### 🔹 ICommandHandler Interface

```csharp
public interface ICommandHandler<in TCommand, TResult>
    where TCommand : ICommand<TResult>
    where TResult : ResultCommonLogic
{
    Task<TResult> ExecuteAsync(TCommand command, CancellationToken cancellationToken = default);
}
```

#### Explanation:

1. `TCommand` aur `TResult` dono **generic types** hai.
2. `where TCommand : ICommand<TResult>`

   * Sirf wahi type `TCommand` use ho sakta hai jo `ICommand<TResult>` implement karta ho.
   * Yeh ensure karta hai ki command handler sirf valid commands handle kare.
3. `ExecuteAsync` method:

   * Yeh **asynchronous** command execution ke liye hai.
   * Command pass kiya jata hai aur result return hota hai.

**Example:**

```csharp
public class LoginCommandHandler : ICommandHandler<LoginCommand, LoginResult>
{
    public async Task<LoginResult> ExecuteAsync(LoginCommand command, CancellationToken cancellationToken)
    {
        // login logic
        return new LoginResult();
    }
}
```

## 2️⃣ Step 2: Create a Command Dispatcher

Dispatcher ek **central point** hai jo command ko **appropriate handler** ko forward karta hai.

```csharp
public class CommandDispatcher : ICommandDispatcher
{
    private readonly IServiceProvider _serviceProvider;

    public CommandDispatcher(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }

    public async Task<TResult> ExecuteAsync<TResult>(ICommand<TResult> command, CancellationToken cancellationToken = default)
        where TResult : ResultCommonLogic
    {
        var handlerType = typeof(ICommandHandler<,>)
            .MakeGenericType(command.GetType(), typeof(TResult));

        dynamic? handler = _serviceProvider.GetService(handlerType);

        if (handler == null)
            throw new InvalidOperationException($"No handler found for command type {command.GetType().Name}");

        return await handler.ExecuteAsync((dynamic)command, cancellationToken);
    }
}
```

#### Explanation Line by Line:

1. **`IServiceProvider _serviceProvider`**

   * DI container ka reference store karta hai.
   * Dispatcher iske through handler ko resolve karta hai.

2. **`handlerType = typeof(ICommandHandler<,>).MakeGenericType(command.GetType(), typeof(TResult))`**

   * Yaha hum dynamically **generic type** create kar rahe hain.
   * Matlab agar command `LoginCommand` hai aur result `LoginResult`, to type banega `ICommandHandler<LoginCommand, LoginResult>`.

3. **`dynamic? handler = _serviceProvider.GetService(handlerType)`**

   * Handler ko DI container se resolve kiya jata hai.
   * Agar DI me register nahi hai, null return hoga.

4. **Null check aur exception throw**

   * Agar handler exist nahi karta, to runtime me error throw hoga.

5. **`return await handler.ExecuteAsync((dynamic)command, cancellationToken);`**

   * `dynamic` use kiya taaki generic type at runtime call ho jaye.
   * Ye dispatcher ko **any command type** handle karne ka ability deta hai.

## 3️⃣ Step 3: Register Commands & Handlers in DI

```csharp
public static IServiceCollection RegisterMediatR(this IServiceCollection services)
{
    // 1️⃣ Register dispatchers
    services.AddScoped<ICommandDispatcher, CommandDispatcher>();
    services.AddScoped<IQueryDispatcher, QueryDispatcher>();

    // 2️⃣ Scan assemblies manually
    var assemblies = new[]
    {
        typeof(Core.Commands.CommandsAssemblyMarker).Assembly,
        typeof(Core.Queries.QueriesAssemblyMarker).Assembly
    };

    foreach (var assembly in assemblies)
    {
        var types = assembly.GetTypes()
                            .Where(t => !t.IsAbstract && !t.IsInterface);

        foreach (var type in types)
        {
            var interfaces = type.GetInterfaces()
                                 .Where(i => i.IsGenericType);

            foreach (var iface in interfaces)
            {
                var genericDef = iface.GetGenericTypeDefinition();

                if (genericDef == typeof(ICommandHandler<,>) ||
                    genericDef == typeof(IQueryHandler<,>))
                {
                    services.AddScoped(iface, type);
                }
            }
        }
    }

    return services;
}
```

#### Explanation:

1. **`AddScoped<ICommandDispatcher, CommandDispatcher>()`**

   * DI container me dispatcher register kiya jata hai.
   * Scope: per HTTP request.

2. **`assemblies` array**

   * Hum manually assemblies ko scan karte hai jahan commands/handlers defined hai.
   * `CommandsAssemblyMarker` ek empty class hoti hai sirf **assembly ko point karne ke liye**.

3. **`assembly.GetTypes()`**

   * Assembly ke sare classes/structs ko get karta hai.
   * `Where(!IsAbstract && !IsInterface)` ensures only concrete classes.

4. **`type.GetInterfaces().Where(i => i.IsGenericType)`**

   * Ye line get karta hai har class ke **generic interfaces** (like ICommandHandler\<LoginCommand, LoginResult>).
   * Matlab jo bhi class ek generic interface implement karti hai, use identify karte hai.

5. **`genericDef == typeof(ICommandHandler<,>)`**

   * Generic interface ka definition check kiya jata hai.

   * Agar match ho, to **DI me register** kar diya jata hai: `services.AddScoped(iface, type);`

   * Isse dispatcher runtime me handler ko resolve kar sakta hai.

## 4️⃣ Step 4: How to Use

### Controller Example:

```csharp
public class AuthController : ControllerBase
{
    private readonly ICommandDispatcher _dispatcher;

    public AuthController(ICommandDispatcher dispatcher)
    {
        _dispatcher = dispatcher;
    }

    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginCommand command)
    {
        var result = await _dispatcher.ExecuteAsync(command);
        return Ok(result);
    }
}
```

#### Explanation:

1. Controller me **dispatcher inject** kiya jata hai.
2. Command ko dispatcher ke through execute kiya jata hai.
3. Dispatcher automatically correct handler ko resolve karta hai.

## 5️⃣ Summary of Key Concepts

| Concept                              | Explanation                                                                   |
| ------------------------------------ | ----------------------------------------------------------------------------- |
| ICommand<TResult>                    | Marker interface for commands with result type.                               |
| ICommandHandler\<TCommand, TResult>  | Handles the command asynchronously.                                           |
| CommandDispatcher                    | Central dispatcher resolving handler dynamically.                             |
| Assembly scanning                    | Automatically finds all command/query handlers and registers in DI.           |
| `where TCommand : ICommand<TResult>` | Generic constraint to ensure type safety.                                     |
| `dynamic` keyword                    | Allows executing generic handlers without knowing exact type at compile time. |

---

## ✅ Benefits of Custom MediatR

1. **Decoupled architecture** — Controller doesn't know about handler implementation.
2. **Centralized execution** — Commands & Queries handled in a single dispatcher.
3. **Flexible** — Easily extendable with validation, logging, transactions, etc.
