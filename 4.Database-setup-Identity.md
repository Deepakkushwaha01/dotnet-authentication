# Database Setup (Identity) in CQRS & Ef core

**Professional Guide: Setting Up PostgreSQL + EF Core Identity in CQRS Architecture**

This guide explains **how to integrate PostgreSQL with ASP.NET Core Identity**, structure your **CQRS layers**, and configure EF Core migrations. Everything is explained **step-by-step**, beginner-friendly, yet professional enough for production-level projects.

---

## **Step 0: Prerequisites**

Before starting, ensure you have:

1. **.NET 9 SDK installed**
    
    ```bash
    dotnet --version
    # Should show 9.x.x
    
    ```
    
2. **PostgreSQL installed and running**
    - Default port: `5432`
    - Create a database for Identity (e.g., `AuthDb`)
3. **dotnet-ef tool installed globally**
    

## **Step 1: Project Structure in CQRS Architecture**

CQRS projects usually have layered architecture:

```
Solution Root
│
├─ Core
│   ├─ Authentication.Core.Commands   → Command handlers
│   ├─ Authentication.Core.Queries    → Query handlers
│   ├─ Authentication.Core.Persistence → EF Core DbContext & Identity
│
├─ API
│   ├─ Authentication.API              → Web API startup, controllers

```

**Key Points:**

- **Persistence Layer**
    - Holds `DbContext`
    - Manages Identity tables
    - Shared between Commands & Queries
- **Commands / Queries**
    - Don’t directly use DbContext for Identity
    - Use `UserManager` / `RoleManager`

## **Step 4: Create Identity DbContext**

Create `AuthenticationIdentity.cs`:

```csharp
using Microsoft.AspNetCore.Identity;
using Microsoft.AspNetCore.Identity.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore;

namespace Authentication.Core.Persistence.Database.Context
{
    public class AuthenticationIdentity : IdentityDbContext
    {
        public AuthenticationIdentity(DbContextOptions<AuthenticationIdentity> options)
            : base(options)
        {
        }

        protected override void OnModelCreating(ModelBuilder builder)
        {
            base.OnModelCreating(builder);

            // Rename default Identity tables for clarity
            builder.Entity<IdentityUser>(b => b.ToTable("Users"));
            builder.Entity<IdentityRole>(b => b.ToTable("Roles"));
            builder.Entity<IdentityUserRole<string>>(b => b.ToTable("UserRoles"));
            builder.Entity<IdentityUserClaim<string>>(b => b.ToTable("UserClaims"));
            builder.Entity<IdentityUserLogin<string>>(b => b.ToTable("UserLogins"));
            builder.Entity<IdentityRoleClaim<string>>(b => b.ToTable("RoleClaims"));
            builder.Entity<IdentityUserToken<string>>(b => b.ToTable("UserTokens"));
        }
    }
}

```

**Explanation:**

- `IdentityDbContext` → provides default Identity tables
- `OnModelCreating` → table rename (optional, for clarity in DB)
- PostgreSQL friendly naming ensures migrations are readable

## **Step 5: Add Design-Time DbContext Factory**

Required for EF Core migrations:

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Design;

namespace Authentication.Core.Persistence.Database.Context
{
    public class AuthenticationIdentityDesignTimeFactory : IDesignTimeDbContextFactory<AuthenticationIdentity>
    {
        public AuthenticationIdentity CreateDbContext(string[] args)
        {
            var optionsBuilder = new DbContextOptionsBuilder<AuthenticationIdentity>();
            optionsBuilder.UseNpgsql("Host=localhost;Database=AuthDb;Username=postgres;Password=yourpassword");

            return new AuthenticationIdentity(optionsBuilder.Options);
        }
    }
}

```

**Explanation:**

- EF CLI needs DbContext at design time
- Hardcoding is okay for dev; production can use environment variables

## **Step 6: Register DbContext and Identity in API**

Create `RegisterDatabase.cs` in API project:

```csharp
using Authentication.Core.Persistence.Database.Context;
using Microsoft.AspNetCore.Identity;
using Microsoft.EntityFrameworkCore;

namespace Authentication.API.Registers
{
    public static partial class Register
    {
        public static IServiceCollection RegisterDatabase(this IServiceCollection services, IConfiguration config)
        {
            // Configure DbContext with PostgreSQL
            services.AddDbContext<AuthenticationIdentity>(options =>
                options.UseNpgsql(config.GetConnectionString("AuthDb")));

            services.RegisterIdentity();

            return services;
        }

        public static IServiceCollection RegisterIdentity(this IServiceCollection services)
        {
            // Required for token providers
            services.AddDataProtection();

            // Identity configuration
            services.AddIdentityCore<IdentityUser>(options =>
            {
                options.Password.RequireDigit = true;
                options.Password.RequireLowercase = true;
                options.Password.RequireUppercase = true;
                options.Password.RequireNonAlphanumeric = false;
                options.Password.RequiredLength = 6;
            })
            .AddRoles<IdentityRole>()
            .AddEntityFrameworkStores<AuthenticationIdentity>()
            .AddDefaultTokenProviders();

            return services;
        }
    }
}

```

**Step-by-Step Explanation:**

1. **AddDbContext** → register `AuthenticationIdentity` in DI container
2. **UseNpgsql** → PostgreSQL provider
3. **AddDataProtection** → required for tokens (email confirmation, password reset)
4. **AddIdentityCore** → configure core Identity services
5. **AddRoles** → enable role-based authorization
6. **AddEntityFrameworkStores** → connect Identity to DbContext
7. **AddDefaultTokenProviders** → enable reset and confirmation tokens

## **Step 7: Configure `Program.cs`**

```csharp
var builder = WebApplication.CreateBuilder(args);

// Register DbContext and Identity
builder.Services.RegisterDatabase(builder.Configuration);

var app = builder.Build();

app.UseHttpsRedirection();
app.UseAuthentication();
app.UseAuthorization();

app.MapControllers();
app.Run();

```

**Explanation:**

- Register services during application startup
- Middleware order is important: Authentication → Authorization

## **Step 12: CQRS Integration Example**

**Command Handler Example:**

```csharp
public class CreateUserCommandHandler : IRequestHandler<CreateUserCommand, Result>
{
    private readonly UserManager<IdentityUser> _userManager;

    public CreateUserCommandHandler(UserManager<IdentityUser> userManager)
    {
        _userManager = userManager;
    }

    public async Task<Result> Handle(CreateUserCommand request, CancellationToken cancellationToken)
    {
        var user = new IdentityUser { UserName = request.Email, Email = request.Email };
        var result = await _userManager.CreateAsync(user, request.Password);

        if (!result.Succeeded) return Result.Failure(result.Errors.Select(e => e.Description));
        return Result.Success();
    }
}

```

**Explanation:**

- Commands do **not directly access DbContext**
- Identity services handle user persistence
- CQRS separation of concern

## ✅ **Tips and Best Practices**

1. **Order matters:** `AddDbContext` must come before `AddEntityFrameworkStores`
2. **Use environment variables for production** connection strings
3. **Scoped DbContext:** do not make singleton
4. **Password policies:** enforce security baseline
5. **Migration commands:** always run from API startup project
